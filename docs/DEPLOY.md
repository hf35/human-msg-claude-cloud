# Развёртывание на VPS

Пошаговая инструкция: от пустого сервера до работающего сервиса с HTTPS. Всё работает в
Docker Compose ([`docker-compose.prod.yml`](../docker-compose.prod.yml)):

| Сервис     | Что делает                                                                         |
| ---------- | ---------------------------------------------------------------------------------- |
| `caddy`    | Единственный, кто открыт наружу (80, 443): HTTPS, статика веба и бэкофиса, прокси  |
| `server`   | API, веб-сокеты, бот, воркер и доставка событий в одном процессе                   |
| `postgres` | База данных (том `pgdata`, наружу не открыта)                                      |
| `migrate`  | Разово применяет миграции и завершается; `server` стартует только после него       |
| `backup`   | Ежедневный `pg_dump` с ротацией, см. [BACKUP.md](BACKUP.md)                        |

Адреса: `https://<домен>/` — веб, `https://<домен>/admin/` — бэкофис,
`https://<домен>/telegram/webhook` — вход для Telegram (только для самого Telegram).

## 0. Что понадобится

- VPS с Ubuntu 22.04/24.04 (или другим Linux с Docker): от 1 vCPU и 2 ГБ памяти. Образы
  собираются на самом сервере, на 1 ГБ сборка может не уложиться: добавьте swap.
- Домен, чьей DNS-записью вы управляете.
- Аккаунт Google (для OAuth) и аккаунт Telegram (для бота).

## 1. Сервер и домен

1. В DNS добавьте запись `A` (и `AAAA`, если есть IPv6) `<домен>` → IP сервера. Caddy получит
   сертификат только когда домен уже указывает на сервер.
2. Откройте порты 80 и 443 (TCP; 443/UDP нужен для HTTP/3). Порт 80 обязателен: через него
   Let's Encrypt проверяет домен. Остальные порты наружу открывать не нужно, база и сервер
   снаружи недоступны. Пример для `ufw`:

   ```sh
   ufw allow OpenSSH && ufw allow 80/tcp && ufw allow 443 && ufw enable
   ```

3. Поставьте Docker с плагином Compose:

   ```sh
   curl -fsSL https://get.docker.com | sh
   docker compose version     # должно напечатать версию
   ```

4. Склонируйте репозиторий и перейдите в него. Все дальнейшие команды выполняются в этом каталоге:

   ```sh
   git clone https://github.com/hf35/human-msg-claude-cloud.git human-msg
   cd human-msg
   alias dc='docker compose -f docker-compose.prod.yml --env-file .env'
   ```

   (`alias` действует до конца сессии; ниже везде `dc` означает эту команду.)

## 2. Google OAuth (вход в веб)

1. [Google Cloud Console](https://console.cloud.google.com/) → создайте проект (или возьмите
   существующий) → **APIs & Services → OAuth consent screen**: тип External, название, почта
   поддержки. Для сервиса достаточно областей по умолчанию (`openid`, `email`, `profile`);
   пока приложение в статусе Testing, войти смогут только добавленные вами тестовые
   пользователи, поэтому для открытого запуска нажмите **Publish app**.
2. **APIs & Services → Credentials → Create credentials → OAuth client ID**, тип
   **Web application**.
3. В **Authorized JavaScript origins** добавьте `https://<домен>` (без слэша на конце и без
   пути). **Authorized redirect URIs** не нужны: используется кнопка Google Identity Services.
4. Скопируйте **Client ID** (вида `1234-abc.apps.googleusercontent.com`) — это `GOOGLE_CLIENT_ID`.
   Секрет клиента (Client secret) сервису не нужен.

Идентификатор клиента вшивается в веб при сборке образа `caddy` (из того же `GOOGLE_CLIENT_ID`),
поэтому после его смены нужна пересборка (`dc up -d --build`). Без `GOOGLE_CLIENT_ID` вход в
веб отключён, остальное работает.

## 3. Telegram-бот

1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → задайте имя и
   username. Сохраните выданный токен — это `TELEGRAM_BOT_TOKEN`.
2. Придумайте секрет вебхука: он нужен, чтобы никто, кроме Telegram, не мог слать боту
   поддельные сообщения. Подойдут буквы, цифры, `_` и `-`:

   ```sh
   openssl rand -hex 32
   ```

3. Вебхук регистрировать вручную не нужно: сервер сам вызывает `setWebhook` на адрес
   `PUBLIC_URL/telegram/webhook` при каждом запуске. Нужно только, чтобы `PUBLIC_URL` был
   публичным адресом `https://<домен>` (см. ниже). Без `TELEGRAM_BOT_TOKEN` сервер работает без бота.

## 4. Настройки (`.env`)

Создайте файл `.env` в каталоге репозитория. Для продакшена достаточно этого набора (шаблон
со всеми переменными и пояснениями — [`.env.example`](../.env.example), но не копируйте его
целиком: его значения рассчитаны на разработку):

```sh
# --- Адрес ---
SITE_ADDRESS=example.com            # домен без https://
PUBLIC_URL=https://example.com      # тот же домен с https://, без слэша на конце

# --- База ---
POSTGRES_PASSWORD=                  # длинный случайный пароль: openssl rand -hex 24

# --- Вход в веб и бот (шаги 2 и 3) ---
GOOGLE_CLIENT_ID=
TELEGRAM_BOT_TOKEN=
TELEGRAM_WEBHOOK_SECRET=

# --- Бэкофис (шаг 5) ---
BACKOFFICE_LOGIN=admin
BACKOFFICE_PASSWORD_HASH=''
```

Остальные переменные (`LOG_LEVEL`, `BACKUP_AT`, `BACKUP_KEEP_DAYS`, `BACKUP_DIR`, `NODE_IMAGE`,
`CADDY_IMAGE` и т. д.) необязательны, значения по умолчанию описаны в `.env.example`.
`NODE_ENV`, `HOST`, `TRUST_PROXY`, `DEV_LOGIN` и `DATABASE_URL` compose задаёт сам, их в `.env`
писать не нужно (вход без Google в продакшене выключен и включить его нельзя).

```sh
chmod 600 .env     # в файле пароли и токены
```

## 5. Пароль бэкофиса

В `.env` хранится не пароль, а его хеш. Получите его командой (она спросит пароль, минимум 8
символов; ничего из репозитория ставить не нужно):

```sh
dc run --rm --no-deps -it server apps/server/node_modules/.bin/tsx apps/server/scripts/hash-password.ts
```

Образ собирается при первом запуске, это займёт несколько минут. Команда напечатает строку вида
`scrypt$16384$8$1$…`. Вставьте её в `.env` **в одинарных кавычках**: в хеше есть знак `$`, который
без кавычек Compose воспримет как подстановку переменной:

```sh
BACKOFFICE_PASSWORD_HASH='scrypt$16384$8$1$…'
```

Бэкофис — это чтение переписок и управление настройками, поэтому пароль должен быть длинным
и уникальным. Попытки входа ограничены по адресу клиента. Дополнительно бэкофис можно закрыть
на уровне Caddy, например паролем или списком адресов; пример в разделе «Закрыть бэкофис
дополнительно» ниже.

## 6. Запуск

```sh
dc up -d --build
```

Что происходит: собираются образы (первый раз 3–10 минут), поднимается `postgres`, `migrate`
применяет миграции и завершается, затем стартуют `server` и `caddy`. Caddy сам получает
сертификат Let's Encrypt для `SITE_ADDRESS`.

Проверка:

```sh
dc ps -a           # postgres, server, caddy, backup: running (healthy); migrate: exited (0)
dc logs server     # «Server listening …», «telegram bot @имя receives updates by webhook»
curl -sI https://example.com/ | head -1                 # HTTP/2 200
curl -s https://example.com/api/me                       # {"error":"unauthorized"}
```

Затем в браузере:

1. Откройте `https://<домен>/`, войдите через Google, задайте вопрос.
2. Откройте `https://<домен>/admin/`, войдите логином и паролем из шага 5. Откройте
   «Настройки» и «Статистику».
3. Напишите боту в Telegram `/start` и отправьте вопрос.

Если что-то не работает, смотрите «Если что-то пошло не так» ниже.

## 7. Обновление

```sh
git pull
dc run --rm backup /deploy/backup.sh once     # бэкап перед обновлением
dc up -d --build
```

`up -d --build` пересобирает изменившиеся образы, заново запускает `migrate` (применяются только
новые миграции) и перезапускает `server` и `caddy`. Данные в томах сохраняются. Миграции идут
до старта нового сервера; если миграция упала, `server` не запускается и работает прежняя версия
(см. `dc logs migrate`).

Изменили `.env`: `dc up -d` применит новые значения к затронутым сервисам.
Сменили `GOOGLE_CLIENT_ID`: нужен `dc up -d --build` (веб пересобирается).

## 8. Эксплуатация

- **Бэкапы** делаются каждую ночь; восстановление и копирование вне сервера — в
  [BACKUP.md](BACKUP.md). Настройте копирование каталога `backups/` на другую машину сразу.
- **Логи:** `dc logs -f server`, `dc logs caddy`. Формат — JSON (pino).
- **Состояние:** `dc ps -a`; проверка процесса и базы — `GET /health` (изнутри:
  `dc exec server wget -qO- http://127.0.0.1:3000/health`).
- **Продуктовые настройки** (сроки, паузы, тихие часы, лимиты) меняются в бэкофисе без
  перезапуска.
- **Перезагрузка сервера:** все сервисы `restart: unless-stopped` и поднимутся сами вместе с Docker.
- **Остановка:** `dc down` (данные сохраняются); `dc down -v` удаляет тома вместе с базой и
  сертификатами, не делайте этого без свежего бэкапа.

## Закрыть бэкофис дополнительно

В [`Caddyfile`](../Caddyfile) в самое начало блока сайта (до первого `handle`) добавьте правило,
которое пускает в `/admin` только ваш адрес (подставьте его):

```caddyfile
	@admin_denied {
		path /admin /admin/*
		not remote_ip 203.0.113.7
	}
	handle @admin_denied {
		respond 403
	}
```

После правки: `dc up -d --build caddy`. Следите, чтобы правило не отрезало вас самих.

## Если что-то пошло не так

| Симптом                                              | Что проверить                                                                                                                                      |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dc up` ругается на `POSTGRES_PASSWORD`              | В `.env` не задан `POSTGRES_PASSWORD`                                                                                                              |
| В `.env` хеш пароля «ломается», вход в бэкофис не идёт | Хеш должен быть в одинарных кавычках (шаг 5); проверьте `dc config \| grep BACKOFFICE_PASSWORD_HASH`                                                |
| `server` не стартует, в логе «Invalid configuration»   | Сообщение называет переменную: например, вебхуку нужны `TELEGRAM_WEBHOOK_SECRET` и `PUBLIC_URL`; логин и хеш бэкофиса задаются вместе             |
| Браузер ругается на сертификат                        | Домен не указывает на сервер или закрыт порт 80/443; `dc logs caddy` покажет ответ Let's Encrypt. Не перевыпускайте часто: у Let's Encrypt лимиты  |
| Кнопки Google нет                                    | `GOOGLE_CLIENT_ID` пуст или менялся без `dc up -d --build`                                                                                         |
| Google: `origin_mismatch` / «Error 400»              | В Authorized JavaScript origins нет точного `https://<домен>` (шаг 2)                                                                              |
| Бот молчит                                           | `dc logs server` (должна быть строка про вебхук); токен верный, `PUBLIC_URL` — публичный https; секрет — только буквы, цифры, `_`, `-`             |
| Бэкофис отвечает 503 на вход                          | Не заданы `BACKOFFICE_LOGIN` и `BACKOFFICE_PASSWORD_HASH`                                                                                          |
| `docker pull` падает с 429                           | Лимит Docker Hub: задайте `NODE_IMAGE` и `CADDY_IMAGE` из зеркала (см. `.env.example`) или подождите                                              |
