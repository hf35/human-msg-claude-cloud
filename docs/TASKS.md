# План задач

Задачи выполняются **по порядку**: каждая опирается на предыдущие. Каждая задача
небольшая, заканчивается проверяемым результатом (тест, команда или видимое
поведение) и делается отдельным коммитом.

Правила продукта — в [`CLAUDE.md`](../CLAUDE.md), устройство системы — в
[`ARCHITECTURE.md`](ARCHITECTURE.md).

**Почему такой порядок.** Сначала каркас и БД, затем ядро с правилами: это самая
рискованная часть, и её можно полностью проверить тестами без UI. Дальше
воркер и доставка, потом API и веб: веб нужен, чтобы вручную гонять сценарии
несколькими пользователями. Затем бот, бэкофис и деплой.

Обозначения: `[ ]` — не сделано, `[x]` — сделано. **Проверка** — как убедиться,
что задача готова.

## Этап 1. Общий пакет `shared`

- [x] **1.1 Каталог текстов на двух языках.** `packages/shared/src/texts/` —

- [x] **1.2 Генератор псевдонимов.** Списки прилагательных и животных на русском
  («Зелёный Кролик») и английском («Green Rabbit»), по 90+ слов в каждом; все
  русские животные мужского рода, поэтому отдельных женских форм нет. Функция
  `randomAlias(locale)` с подменяемым источником случайности. **Проверка:**
  юнит-тест: формат, языки не смешиваются, размер списков, есть разнообразие и
  достижимы все слова, результат повторяем при заданном источнике.
- [x] **1.3 Проверка текста сообщения.** `validateMessageText(text, maxLength)`
  возвращает очищенный текст или причину отказа (`empty`, `tooShort`,

  невидимых символов, удаление управляющих символов (в том числе NUL, который не
  сохранить в PostgreSQL), длина в видимых символах, защита от огромных текстов.
  **Проверка:** юнит-тесты на все случаи.
- [x] **1.4 Тихие часы.** `isQuietHours(now, range, tz)` и `parseTimeRange`
  (диапазон `ЧЧ:ММ-ЧЧ:ММ`): переход через полночь, начало входит, конец нет,
  равные границы выключают тихие часы, переход на летнее время. **Проверка:**

- [x] **1.5 Типы настроек.** zod-схема настроек с значениями по умолчанию из

### Из независимого аудита ([`AUDIT.md`](AUDIT.md))

Пункты аудита, которые не нужны для запуска MVP. Номер в скобках — номер пункта в
аудите. Пункты 3, 8 и 9 дёшево закрыть сразу при работе над этапами 6–7 (там
соответствующий код пишется с нуля), поэтому, дойдя до них, стоит заглянуть сюда.

- [ ] **П.1 Закрытая вкладка (2).** Не держать назначение 30 минут после закрытия
  вкладки: если у веб-пользователя нет соединений 1–2 минуты, снимать
  назначение без паузы. **Проверка:** тест со сдвигом времени.
- [ ] **П.2 Намерение в сообщении веба (3).** Клиент передаёт «ответ на
  назначение X» или «вопрос»; сервер отклоняет сообщение при несовпадении, и
  вопрос не уходит незнакомцу как ответ. **Проверка:** тест API.
- [ ] **П.3 Быстрый подбор получателя (4).** Заменить `ORDER BY random()` по всем
  подходящим на выбор по индексируемому полю (последняя активность или
  назначение) с небольшой случайностью. **Проверка:** замер на 100 тыс.
  пользователей, подбор укладывается в ~50 мс.
- [ ] **П.4 Разбор очереди от получателей (5).** Находить пользователей, у
  которых закончилась пауза, и вызывать для них `assignFromQueue`, вместо
  обхода 100 старейших вопросов (они могут закрыть путь новым). **Проверка:**
  тест: 100 вопросов без подходящих получателей не мешают 101-му.
- [ ] **П.5 Политика хранения и удаление аккаунтов (7).** Решить, сколько хранить
  переписки; ввести `ON DELETE` или обезличивание вместо `no action`.
  **Проверка:** тест удаления пользователя с историей.
- [ ] **П.6 «Призраки» web_connections (8).** Очищать таблицу при старте сервера
  и/или учитывать время последнего ping. **Проверка:** тест: запись без
  свежего ping не делает пользователя доступным.
- [ ] **П.7 Дедлайн и недоставка (9).** Если Telegram отвечает временными
  ошибками, не тратить дедлайн получателя: начинать отсчёт после доставки или
  снимать назначение. **Проверка:** тест адаптера с ошибкой доставки.
- [ ] **П.8 Защита от флуда (10).** Ограничитель частоты сообщений перед ядром,
  чтобы отклонённые сообщения не плодили транзакции, строки outbox и `NOTIFY`.
  **Проверка:** тест: поток сообщений от одного пользователя обрезается.
- [ ] **П.9 Больше псевдонимов (11).** Расширить списки слов или делать
  псевдонимы из трёх слов; поиск занятых вариантов по индексу вместо
  `LIKE 'base %'`. **Проверка:** тест уникальности на 100 тыс. псевдонимов.
- [ ] **П.10 Повторяющийся код ядра.** Вынести шаблон «заблокировать
  пользователя и найти его активное назначение», который повторяется в
  `submitAnswer`, `skipAssignment`, `reportQuestion`, `markUndeliverable` и
  воркере. **Проверка:** тесты не меняются и проходят.
